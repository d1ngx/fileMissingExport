# fileMissingExport

KodBox 插件：导出网盘中「数据库有记录、存储里找不到物理文件」的失效记录，支持断点续扫和谨慎的数据库清理。

## 失效文件

网盘列表能看到（`io_source` 有记录），但对应存储路径 `IO::exist` 为假。也包括存储记录缺失、所属存储已删除。存储一时连不上（访问异常）会记入导出，**清理时会跳过**，避免误删。

## 安装

将本目录放到 KodBox 的 `plugins/fileMissingExport/`，在 **插件中心** 启用，打开该插件的 **设置**。

仅系统管理员可扫描和清理。

## 扫描导出

1. 可选：限定存储、是否含回收站 / 历史版本。
2. 「每批条数」默认 300，表示每次从数据库取出并检查的记录数，**不是只扫 300 个**。前端会自动连续请求，直到全部扫完。
3. 点 **开始扫描**。可暂停、继续；**重新开始** 会新开一轮结果目录。
4. 完成后下载 **CSV**（Excel）或 **TXT**（逐条可读）。记录含网盘路径、系统路径、存储路径、原因等。

百万级请保持设置窗口打开以自动续跑；关掉后点「继续」从断点恢复。

结果与日志目录：`data/temp/log/fileMissingExport/<runId>/`（`state.json`、导出文件、`clean-log.txt`）。

## 清理数据库（危险）

扫描完成且本轮有失效记录后，进度条下方会出现清理区。

1. 先下载导出文件，建议备份数据库。
2. 点 **清理失效记录**，确认后再输入大写 `DELETE`。
3. 只处理本轮扫描清单；删除前会再核对物理文件，已恢复的跳过。
4. 会删除对应的网盘记录、历史版本、分享/回收站引用，以及已无引用的 `io_file` 等。**不会删除磁盘上仍存在的文件。**
5. 可暂停后点 **继续清理**。

未完成扫描、或旧版本扫描没有清单时，清理按钮不可用，需重新扫一轮。

## 注意

请确认存储可访问，避免网络故障被误判为文件丢失。清理不可恢复。
